## 2. Технические допущения

Эти решения приняты при подготовке дизайна. Они описывают будущий MVP и не означают, что соответствующие компоненты уже реализованы.

| Область | Решение и основание |
| --- | --- |
| Источник данных | RCAEval RE2-OB: 90 контролируемых инцидентов Online Boutique с метриками, логами и трассами. Состав подтверждён по опубликованным метаданным; EDA не выполнялся. |
| Пользователь продукта | Дежурный SRE-инженер. Заказчик и коммерческий спрос пока не подтверждены. |
| Модель | Готовая LLM через API с поддержкой вызова инструментов; перед сравнением фиксируются модель, версия, параметры и тариф. Дообучение не требуется. |
| Архитектура | Один агент и один локальный MCP-сервер с инструментами только для чтения. Мультиагентное взаимодействие в первую итерацию не входит. |
| RAG | BM25 по небольшому версионируемому корпусу описаний сервисов и инструкций. Готовых runbook’ов в датасете нет; корпус готовится отдельно от тестовых инцидентов. |
| Интерфейс | Локальный CLI; JSON и Markdown на выходе. Команда и формат описываются как будущие интерфейсы. |
| Начало инцидента | Время внедрения сбоя используется как известный момент учебного сигнала. Это упрощает задачу и не проверяет обнаружение инцидентов. |
| Сравнение | Простое ранжирование аномалий метрик; фиксированный сбор данных с одним вызовом LLM; адаптивный агент с той же LLM. |
| Разбиение | 54/18/18 случаев для разработки, валидации и теста; группировка по «сервис × тип сбоя», seed 42. Все шесть типов и пять сервисов представлены в каждой части; три повтора одной группы не разделяются. |
| Ограничения разбора | Не более 12 вызовов инструментов, 120 секунд и $0,10 на один разбор. Начальные проектные ограничения, выполнимость проверяется пилотом. |
| Критерий качества | Гипотеза: Top-1 сервиса минимум на 10 процентных пунктов выше фиксированного LLM-baseline при тех же пределах ресурсов. Это не полученный результат. |
| Средства разработки | Сохранить Python 3.13 и uv; использовать Ruff для линтинга и форматирования, pre-commit для Git-hook. |

Конкретный провайдер LLM не закреплён на этапе ДЗ №1. В последующей итерации сначала проверяется доступность вызова инструментов и стоимость на части данных разработки. Выбранная конфигурация фиксируется до валидационного сравнения и не меняется по результатам финального теста.

Для разбиения отсортированные списки пяти сервисов и шести типов сбоя перемешиваются последовательно одним генератором `random.Random(42)`: сначала сервисы, затем типы. Для типа с индексом `i` группа сервиса `i % 5` попадает в валидацию, группа сервиса `(i + 1) % 5` — в тест, остальные три группы — в разработку. Все три повтора остаются вместе. Состав сохраняется в манифесте и проверяется на отсутствие пересечений и покрытие классов. Тест проверяет новые сочетания известных сервисов и типов сбоя, а не перенос на неизвестный сервис.

В финальном тесте 18 случаев, но только шесть независимых групп сценариев. Прибавка на два правильных ответа равна 11,1 процентного пункта и уже превышает целевые 10 пунктов. Поэтому этот порог служит ориентиром MVP; статистически устойчивое преимущество потребует расширенной оценки. Существование ссылки на наблюдение можно проверить автоматически, поддержку вывода этим наблюдением — вручную. Полной эталонной разметки объяснений в выбранном наборе нет.

## 3. Журнал решений

| Этап | Решение | Почему |
| --- | --- | --- |
| Выбор темы | Остановиться на агенте диагностики инцидентов. | Пользователь выбрал эту задачу для ДЗ №1. Ранее обсуждавшиеся темы в текущий scope не входят. |
| Уточнение назначения | Диагноз и рекомендации для учебного микросервисного приложения. | Позволяет определить пользователя, входы и проверяемый результат без доступа к production. |
| Выбор эксперимента | Сохранённые инциденты вместо работающего стенда. | Основной объём работы приходится на диагностику и оценку, а не эксплуатацию Kubernetes. |
| Выбор данных | RCAEval RE2-OB. | Есть разные источники телеметрии и известная внедрённая причина; требуется защита от утечки разметки. |
| Выбор ML-части | Готовая LLM, MCP и небольшой RAG. | Соответствует интересу к агентам и инструментам при ограниченном бюджете. |
| Разделение этапов | В ДЗ №1 подготовить дизайн и окружение; реализацию и эксперименты выполнять позже. | Это соответствует требованиям первого задания. |
| Подготовка сдачи | Локальная ветка `hw_1`, сохранение исходных учебных материалов. | Требуемая ветка для первой работы; публикация отдельно от локальной подготовки. |

| Требуемые разделы и относительные ссылки Markdown | Все шесть разделов задания присутствуют; локальные ссылки ведут на существующие файлы. |
