# Агент диагностики инцидентов микросервисного приложения

Учебный проект курса ML System Design. Агент помогает дежурному SRE-инженеру определить вероятный проблемный сервис и причину сбоя по метрикам, логам и трассам. Результат разбора содержит подтверждающие наблюдения, альтернативные гипотезы и рекомендации для следующей проверки. Исправления выполняет инженер.

**Статус:** подготовлены дизайн системы и окружение разработки для ДЗ №1. Агент, MCP-сервер, поиск по инструкциям и оценочный стенд ещё не реализованы. Экспериментальные результаты отсутствуют; цели качества в документации — гипотезы для проверки.

## Первая итерация проекта

Планируем использовать сохранённые инциденты Online Boutique из [RCAEval RE2-OB](https://huggingface.co/datasets/phamquiluan/RCAEval): метрики, логи, трассы и известные причины контролируемых сбоев. Полный датасет в репозиторий не включён.

Один агент с готовой LLM через API будет запрашивать телеметрию через локальный MCP-сервер и искать общие инструкции диагностики в небольшой базе знаний. Для первого MVP достаточно BM25. Предполагаемый интерфейс — локальный CLI с отчётом в JSON и Markdown; команд запуска агента пока нет.

Агент будет сравниваться с фиксированной последовательностью сбора данных и одним вызовом той же LLM, а также с простым ранжированием аномалий метрик. Случаи разработки и итогового теста будут разделены по сочетанию сервиса и типа сбоя. Правильные ответы и исходные имена папок с разметкой агенту недоступны.

В первую итерацию не входят обучение весов, самоэволюция, живой Kubernetes, автоматическое исправление инцидентов и подключение к production. Бюджет будущих API-экспериментов — до $50. Для настройки репозитория API-ключи не нужны.

## Окружение разработки

Нужны Git и [uv](https://docs.astral.sh/uv/getting-started/installation/). Версия Python зафиксирована в `.python-version` — 3.13. Следующие команды устанавливают окружение разработки и локальный Git-hook:

```bash
uv python install 3.13
uv sync --locked
uv run --frozen pre-commit install
```

Разрешённые версии зависимостей записаны в `pyproject.toml`, точные версии — в `uv.lock`. Pre-commit использует Ruff из этого же окружения, поэтому отдельной версии линтера у Git-hook нет.

## Проверки

```bash
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen pre-commit run --all-files
git diff --check
```

Для форматирования Python-кода:

```bash
uv run --frozen ruff format .
```

При коммите запускаются линтер и форматер. Если форматер изменил файл, нужно проверить изменения, снова добавить файл в индекс и повторить коммит. Ruff проверяет Python-код; факты, ссылки и схемы документации проверяются отдельно.

`src/mlsd_2026/__init__.py` содержит исходную заготовку пакета. Команда `mlsd-2026` пока выводит приветствие и не выполняет диагностику. Тестов поведения агента на этапе ДЗ №1 нет.

## Структура

```text
docs/                Дизайн системы и принятые решения
src/mlsd_2026/       Исходная Python-заготовка
tasks_log/           Условие задания и предоставленный шаблон
pyproject.toml       Метаданные проекта, зависимости и настройки Ruff
uv.lock              Зафиксированные версии зависимостей
.pre-commit-config.yaml
```

Секреты, скачанные данные и результаты будущих запусков размещаются в исключённых из Git `.env`, `data/`, `artifacts/` и `runs/`. Перед сдачей нужно создать PR из `hw_1` в `main` и назначить reviewers; публикация не входит в текущую локальную подготовку.
